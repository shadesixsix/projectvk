# Квиз-платформа (реалтайм-викторины)

Веб-приложение для проведения квизов в реальном времени в стиле Kahoot: организатор
создаёт квиз и запускает игру, участники подключаются по коду комнаты и отвечают на
вопросы синхронно, по завершении показывается лидерборд, а результаты сохраняются в историю.

Это MVP, полностью закрывающий заявленные требования проекта.

---

## Возможности

- **Регистрация и авторизация** пользователей с ролями: **организатор** и **участник**.
- **Создание и настройка квизов**: категория, время на вопрос, базовые баллы, бонус за скорость.
- **Вопросы разных типов**: текстовые и **с изображением**, с **одиночным** и **множественным** выбором.
- **Проведение в реальном времени**: код комнаты, подключение участников, синхронный показ
  вопросов, таймер. Ответить можно **только пока вопрос показывается** (сервер отбрасывает поздние ответы).
- **Подсчёт баллов и определение победителя**: очки за правильный ответ + бонус за скорость,
  промежуточный и финальный лидерборд, пьедестал.
- **Личный кабинет**: у организатора — свои квизы и проведённые игры; у участника — история участия
  с местами и очками; страница подробных результатов любой игры.

## Технологический стек и почему он выбран

| Слой | Технология | Обоснование |
|------|-----------|-------------|
| Клиент | **React + Vite** | Быстрый старт, компонентный UI, требование методички |
| Сервер | **Node.js + Express** | Единый язык с клиентом (JavaScript), простой REST API |
| Реалтайм | **Socket.IO (WebSocket)** | Комнаты, широковещательная рассылка вопросов, синхронный таймер |
| База данных | **SQLite (встроенный модуль `node:sqlite`)** | Не требует установки и компиляции — ноль зависимостей и рисков при запуске; полноценная реляционная БД |
| Авторизация | **JWT + bcryptjs** | Пароли хранятся в виде хэша; тот же токен используется для REST и WebSocket |

Ключевая идея архитектуры: **во время игры состояние живёт в памяти сервера**, а в базу
пишутся только итоги (баллы, места, история). Это самая простая и стабильная схема для
викторины «здесь и сейчас».

## Модель базы данных

```
users(id, username, password_hash, role, created_at)
quizzes(id, owner_id→users, title, category, description, time_limit, points_base, speed_bonus, created_at)
questions(id, quiz_id→quizzes, text, image_url, type, time_limit, position)
options(id, question_id→questions, text, is_correct, position)
sessions(id, quiz_id→quizzes, host_id→users, room_code, status, created_at, finished_at)
session_players(id, session_id→sessions, user_id→users, nickname, score, rank)
```

Изображения вопросов хранятся прямо в БД как `data:`-URL (клиент автоматически уменьшает
картинку) — благодаря этому не нужен ни отдельный файловый сервер, ни загрузка файлов.

## Запуск

**Требуется:** Node.js версии 22 или новее (встроенный `node:sqlite`).

```bash
# 1. Установить зависимости (один раз)
npm install

# 2. Запустить сервер и клиент одной командой
npm run dev
```

Откройте в браузере **http://localhost:5173**

- Клиент (Vite): http://localhost:5173
- Сервер (API + WebSocket): http://localhost:4000

### Демо-данные (необязательно)

Пока сервер запущен, в отдельном терминале:

```bash
npm run seed
```

Создаст готовые аккаунты и демонстрационный квиз:

| Роль | Логин | Пароль |
|------|-------|--------|
| Организатор | `demo` | `demo` |
| Участник | `player1` | `player1` |
| Участник | `player2` | `player2` |

### Автоматический тест игрового движка

```bash
npm test
```

Сквозной тест: имитирует организатора и двух участников через WebSocket, проходит
целую игру и проверяет подсчёт баллов, определение победителя и сохранение истории.

## Как провести квиз

1. Войдите как **организатор** → «Создать квиз» → добавьте вопросы.
2. Нажмите **«Провести квиз»** — появится **код комнаты**.
3. На других устройствах/во вкладках войдите как **участники**, введите код на главном экране.
4. Организатор нажимает **«Начать игру»** и ведёт квиз кнопкой «Следующий вопрос».
5. По окончании — лидерборд и пьедестал, результаты попадают в историю.

> Для проверки на одном компьютере откройте участников в **разных браузерах**
> (или в режиме инкогнито), т.к. вход хранится в localStorage браузера.

## Структура проекта

```
quiz-app/
├── package.json          # npm workspaces + команды dev/build/seed/test
├── client/               # фронтенд (React + Vite)
│   └── src/
│       ├── pages/        # экраны: вход, кабинет, редактор, проведение, игра, результаты
│       ├── api.js        # запросы к серверу
│       ├── socket.js     # подключение Socket.IO
│       └── auth.jsx      # контекст авторизации
├── server/               # бэкенд (Node + Express + Socket.IO)
│   └── src/
│       ├── index.js      # точка входа (HTTP + WebSocket)
│       ├── db.js         # база данных и схема (node:sqlite)
│       ├── auth.js       # регистрация/вход/JWT
│       ├── quizzes.js    # CRUD квизов и вопросов
│       ├── history.js    # история и результаты
│       └── game.js       # игровой движок реального времени
└── scripts/              # seed (демо-данные) и smoke (тест)
```

## Сборка «в один порт» (для демонстрации)

```bash
npm run build     # собирает клиент в client/dist
npm start         # сервер отдаёт и API, и готовый клиент на http://localhost:4000
```
